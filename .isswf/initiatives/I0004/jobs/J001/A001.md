## npm string-bin decision (verified)
Read npm-normalize-package-bin (bundled with npm 12.2.0) and ran `npm install --package-lock-only --offline` on temp manifests (Node 26.8.1):
- `"bin":"./tools/x.mjs"`, name `a` gives lock bin `{"a":"tools/x.mjs"}`.
- Same with name `@s/pk` gives `{"pk":"tools/x.mjs"}`, so the scope is stripped.
- Object `{"foo":"./t/x.mjs"}` gives `{"foo":"t/x.mjs"}`, so a leading `./` is stripped in object form too.
- Array form gives `{"x.mjs":"t/x.mjs"}`. I do not support it: it yields undefined, so a lock with bin is rejected (fail closed).
String and object forms are supported. Keys and targets are normalized as npm does: `\` to `/`, `join('/')` and strip the leading `/`. Any invalid entry makes the whole bin undefined, which is stricter than npm (npm skips the entry).
The `[\\:]` key replacement and the backslash-target path were ported from the library source and not run through npm (my shell test of the backslash case failed on quoting).
