## Design
- `src/progress.ts`: `Progress { run(label, work), clear() }`, `createProgress({stream, env, now, timers})`, `NO_PROGRESS`. Imports `animationEnabled`, `formatElapsed`, `SPINNER_FRAMES`, `SPINNER_TICK_MS`, `STATIC_GLYPH` directly from `src/tui/working-model.ts` (pure module, no Ink import, `package-boundaries` test unaffected). Nothing moved or duplicated.
- Modes: TTY + animation -> `\r\x1b[2K` redraw of `<frame> <label>… [Ns]` every 80ms (elapsed from 1s), line truncated to `columns-1`, erased in `finally`; TTY + `AGENT_DEPOT_NO_ANIMATION=1` -> one persistent `· <label>…` line, no timer; non-TTY -> one plain `<label>…` line per step. Timer is `unref()`'d and `clearInterval`'d in `finally` (success and throw). A step started inside another step is not shown separately.
- `runCli` wraps both `output` (stdout) and `errorOutput` so every line printed mid-step first erases the spinner (several wrapped steps print while running: `inspectSkillRemovals` callback, `applyProfileImport`, `executeSingleInstall`, export's stderr preview). stdout payload is never altered. `export` now receives the wrapped stderr writer.
- Seam: `CliDependencies.progress?: Progress`. Default is `createProgress()` on `process.stderr`, EXCEPT when `dependencies.stderr` is injected (then `NO_PROGRESS`), so the ~200 existing `runCli` tests that capture stderr lines are untouched. Decision for review: an embedder that injects `stderr` gets no progress unless it passes `progress`.
- `runAppCommand`, `runPackageCommand`, `runProfileExport/Import` take an optional trailing `progress` (default `NO_PROGRESS`), so direct callers are unaffected.

## Remaining risks / notes
- Injected-`stderr` embedders get no progress by default (see Seam); progress is not routed through the line-based `stderr` callback to avoid changing captured output.
- Spinner output width uses code-point count, not display width (labels with wide characters could under-truncate on very narrow terminals).
- Ctrl-C during an animated step leaves the last frame on the line (no signal cleanup); cursor is never hidden so the terminal stays usable.
