### Diagnosis of the 3 long-TMPDIR e2e failures (isswf-debug): all three are test fragility, none is a product defect
Method: ran each at `TMPDIR` of 48 chars, patched the dist copy to print the screen at the failing assertion, compared with baseline `15b7fdd` (all three fail there too).
- "the Xeo semantic palette reaches colored text": the Sources row `fixture-app app <long recipe path> · needs approval` wraps the status onto two rows (`needs` / `approval`), and Ink colors each wrapped row separately, so the escape sequence for the contiguous text `needs approval` never appears. The row wraps naturally and nothing overlaps. Fix: accept the warning color on `needs approval` or on both words.
- "narrow recipe approval keeps all execution terms reachable before consent": it presses `k` and waits a fixed 20 ms before asserting `Scroll to end before y` (App recipe gate, not touched). With the longer plan (117 rows) the PTY frame had not updated yet; the screen printed was still `Review 117 of 117`. Fix: `session.send("k", /Scroll to end before y/u)` (wait for the frame).
- "the narrow TUI keeps recipe approval separate from confirmed App installation and updates": two assertions read the whole working directory from one screen or one string: the install preview's last page shows only the tail of a path wrapped over three rows, and the uninstall preview keeps the `│` border between wrapped rows. Fixes: the install path is rebuilt from the pages' row windows (`pagedRows` over the visited screens), and the uninstall string drops box characters before comparing.
