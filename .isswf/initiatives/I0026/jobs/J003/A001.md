## Diagnosis (issue #92)

- Environment: Windows 11 Pro 10.0.26300.9818, Node v26.12.1, @homebridge/node-pty-prebuilt-multiarch 0.14.1. The backend is ConPTY via the system API: `_useConpty=true`, `_useConptyDll=false`, chosen automatically because build >= 18309.
- Reproduction, from Git Bash (this agent's shell): `node --import ./dist/tests/isolated-env.js --test --test-timeout=120000 --test-name-pattern="walks every view" dist/tests/e2e/tui.e2e.test.js`. The result is `Timed out waiting for /AGENT DEPOT[\s\S]*n add ·/u; child still running; 3281 raw chars received`, plus `Error: AttachConsole failed` from `conpty_console_list_agent.js:17`. The screen was stuck on "Loading sources…".
- Probe: a scratch script spawned `dist/src/cli.js tui` through node-pty at 110x40 and captured the raw stream for 8 to 35 s.
  - Output stops growing at 3241 chars within about 3 s, and the stripped text contains `n add ·`. The TUI itself renders the expected frame.
  - Synchronized-update marker positions: `?2026h` at 302, `?2026l` at 318, `?2026h` at 1399, `?2026l` at 1415. Each pair is empty (16 bytes apart). The frame content, including `n add` at 1377 and the whole final frame up to 3241, is emitted outside or after the pairs.
- Causal chain: the TuiSession harness (tests/e2e/tui.e2e.test.ts, `updateScreen`) promotes cells to the completed frame only on `?2026l`. `waitFor` also requires the completed-frame count to increase. ConPTY re-renders the console buffer itself and passes the 2026 markers through immediately, so they no longer bracket the frame. As a result, the last complete frame the harness sees is the stale "Loading sources…" one, and `waitFor` times out after 30 s.
- AttachConsole failed is a side effect, not the cause. It is raised by the forked `conpty_console_list_agent` during `terminal.kill()` in the test's cleanup, after the timeout. It occurred in every parent tried.
- Parent-console dependence was rejected. Git Bash, `pwsh -NoProfile -Command` and a new conhost console window (cmd started through `Start-Process`) all produced the same 3241-byte stream, the same empty marker pairs and the same AttachConsole error. Following later coordinator guidance, a separate visible window should not have been used. The first attempt, `cmd //c "start /wait ..."` from Git Bash, failed to quote the command and most likely caused the "Windows no encuentra el archivo" dialog on the operator's desktop. The `Start-Process` run completed (exit 0). IDE terminals were not tested.
- Alternatives rejected:
  - winpty (`useConpty:false`) emits no `?2026` markers and no `?1049h`. The journey asserts the alternate screen, and frame gating would never complete.
  - Bundled conpty.dll (`useConptyDll:true`) fails with "Cannot find conpty.dll at ...build\Release\conpty\conpty.dll" because the installed package did not copy it. Fixing that means editing node_modules or changing the dependency, which is excluded.
  - A Windows-specific frame heuristic in the harness was not attempted. It would mean the Windows run uses a different oracle than Linux, which is beyond the spawn configuration.
- Regression seam: none. The behavior belongs to the OS pty layer, and the skip reason appears in the test output.
