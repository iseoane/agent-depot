isswf-debug (symptom, hypotheses, causal chain):
- Symptom: teardown `rm` fails with ENOTEMPTY when a view still takes `SourceStateStore` locks (mkdir `*.lock`, state writes) under the fixture dir (#45 mechanism).
- Natural reproduction does NOT occur on Linux: 24-way load, every tui test file (32 files incl. .ts) x 24 runs = 768 runs: 0 ENOTEMPTY (6 unrelated failures: 5 package-journey 5s frame timeouts under overload, 1 file-picker symlink assertion; neither is ENOTEMPTY). So the RED reproductions are injected (brief allows "injected lock delay in dist"; all preloads are scratchpad-only, nothing committed):
  1. `teardown-probe.mjs` (strict): wraps node:fs/promises; at each test-hook `rm -r` it records fixture ops still in flight and any op under that root afterwards; mutating ops after teardown start = violation, process exits 1.
  2. `widen-race.mjs`: teardown rm empties a dir, pauses 150 ms, then rmdir; a lock taken during teardown is held 400 ms. Produces the literal ENOTEMPTY.
  3. `slow-view-lock.mjs`: delays a `*.lock` mkdir requested from sources-view.js (async stack) by 250 ms, to reproduce the known latent sources-recipes case.
- Causal chain (observed, not inferred): the final awaited frame still has a Working line (view mounting/reloading) -> the view's async chain keeps calling listSources/packages lock/status reads under the fixture -> teardown starts -> lock mkdir lands in the rm window.
