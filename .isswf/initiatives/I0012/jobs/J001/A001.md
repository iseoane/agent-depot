## Deviations
1. NOT `detached: true` / process-group kill (acceptance 1 said "whole process group"; acceptance 2 allowed choosing another approach). Evidence:
   - `detached: true` makes libuv call setsid(): the child loses its controlling terminal. Probe under a pty (`script -qec`): detached=false -> `has-ctty`, detached=true -> `no-ctty`. git/ssh prompt via /dev/tty (CHANGELOG already states git steps may prompt on the terminal), so detaching would break credential and host-key prompts.
   - Ctrl-C: throwaway hack (detached: true in src, reverted, not committed) against the new guard test: FAIL "grandchild 1889454 is still running". A terminal's group-wide SIGINT no longer reaches a detached child, and agent-depot has no SIGINT handler in src to forward it, so the child would be orphaned.
   - Chosen instead: the child stays in agent-depot's group and session. On terminate, take a single `ps -A -o pid=,ppid=` snapshot (before any signal), SIGTERM the child and all its descendants, SIGKILL those still alive after 2 s, then destroy stdout/stderr and settle after another 2 s as on win32. If `ps` fails, only the direct child is signalled.
   - Post-fix check under a pty that the child still has a controlling terminal through runProcess: `has-ctty`. Ctrl-C guard test (driver in its own process group, test sends `kill(-pgid, SIGINT)`) stays green.
2. Result shape: runner kill still reports `(code null, signal "SIGTERM")`, including after SIGKILL escalation (settle normalises SIGKILL/null to SIGTERM when the runner killed it). Consequence: a child that handles SIGTERM and exits with its own code after a timeout is now also reported as terminated (code null) instead of its code; callers already check timedOut/outputTooLarge/signal (app-flow only tests `signal` truthiness).
3. Shared grace constant renamed WINDOWS_KILL_GRACE_MS -> KILL_GRACE_MS (2 s); win32 timing unchanged.

## Known limits (named, not fixed)
- A process that left the tree before the kill (daemonized, or orphaned because the direct child already exited and a grandchild holds the pipes) is not killed; the bounded settle returns the result but the process leaks. Covered by the "left the process tree" test.
- Descendants spawned between the `ps` snapshot and the SIGTERM can escape; pid reuse between snapshot and SIGKILL is theoretically possible within the 2 s grace (the child's own pid is skipped once it has exited).
