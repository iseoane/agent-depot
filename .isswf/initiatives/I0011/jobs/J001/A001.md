## Changes
- `src/process-runner.ts`: `withChildOutput(sink, work)` via `AsyncLocalStorage`; `runProcess` taps stderr always and stdout when it is not captured data (or the caller sets new `streamStdout`). Stdout is piped (and discarded) only when a sink exists. Capture, caps, `terminate()` and the result shape (timedOut/outputTooLarge/SIGTERM from #47) are untouched; the tap is read-only, covered by a deep-equal test over success, stdout cap, stderr cap and timeout.
- `src/progress.ts`: takes an injected `tapChildOutput` (type declared locally, no import of the process runner; without it no child output is shown); tail of the last 3 lines drawn under the spinner on the existing 80 ms tick, `ESC[nA ESC[J` erase only when a tail exists (single-line frames still emit the old `ERASE_LINE`, so existing progress tests are unchanged); lines are cut by display width (`string-width`), stripped of terminal escapes/control characters, `\r` progress reduced to its last state, line buffer capped; no tail when `stream.rows` is too small; the tap goes inert when the step ends. `createProgress({ verbose })`: plain step line, then each child line to the stream as it arrives (also for `mayPrompt` steps, since plain lines are prompt-safe).
- `src/cli.ts`: wires `withChildOutput` into `createProgress`; global `--verbose` stripped from argv wherever it appears; help text documents it. `src/app-flow.ts`, `src/package-flow.ts`: lifecycle commands set `streamStdout: true` (their captured stdout is the command log).
- Decision on what is shown: stderr always; stdout unless the caller captured it as data (git tree reads, `npm root`, version/latest probes, `runPiGit`), which stays hidden so binary or machine output never reaches the tail or `--verbose`. Lifecycle commands opt in.
- Docs: `CHANGELOG.md` (Unreleased/Added, two entries), `README.md` (progress paragraph with `--verbose`), `tests/e2e/README.md`.
- Tests: `tests/child-output.test.ts` (new), `tests/cli-options.test.ts`, `tests/cli.test.ts` (exact usage text), `tests/child-output.test.ts` also passes the tap explicitly and floods one stream per cap case (flooding both was a race between the streams that flaked once), `tests/progress-fixtures.ts` (`rows`, `screenOf` terminal replay), `tests/fake-app-fixture.ts`, `tests/e2e/tui.e2e.test.ts`.
- TUI: CLI only. The Working indicator is an Ink component and has no stderr tail surface; the sink is simply absent there, so TUI behavior is unchanged. Not "trivial", so left out as the brief allows.

Remaining risks / notes for review
- Child output written straight to `/dev/tty` during an animated, non-`mayPrompt` step (an App recipe running `sudo`, a Package lifecycle step running `git`) is now erased more thoroughly than before: the redraw clears from the spinner row downward (`ESC[nA` then `ESC[J`) instead of one line. This is the residual raised in the issue's first comment; not fixed here. `mayPrompt` steps (git refresh/install, profile import) stay static and are unaffected, and `--verbose` is prompt-safe.
- Under `--verbose`, a failing command's stderr appears twice (streamed live, then in the existing failure message); left as is per "failure output as today".
- Flag policy: `--verbose` is stripped anywhere in argv, including as the value of another option (for example `--skill --verbose`); judged acceptable.
- The tail redraws on the 80 ms tick, so a very short step may never show its output (intentional throttling).
- Tail/verbose lines are sanitized, so child color codes are not preserved.
- `AGENT_DEPOT_NO_ANIMATION=1` on a TTY keeps the static line and shows no tail (matches the issue).
