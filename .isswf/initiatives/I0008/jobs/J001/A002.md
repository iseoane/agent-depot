## Product bugs found (separate `fix(win32)` commits)
1. **d9e37ee, Pi checkout root check.** `readPiCheckoutEvidence` compared `git rev-parse --show-toplevel` (forward slashes, long names on Windows) with `path.resolve(checkoutPath)` (backslashes, possibly an 8.3 short name). User-visible impact: on Windows every Pi Package checkout looked "not the root of its Git checkout", so installed-version and update evidence was lost and Package updates were reported unavailable. Fix: compare `realpath` of both.
2. **6885005, lock retry.** The Source state, Package state and Git cache lock loops only retried on `EEXIST`. Windows returns `EPERM`/`EACCES` from `mkdir` while the holder's `rmdir` is completing. User-visible impact: two concurrent Agent Depot processes (for example the TUI and a CLI command) could fail with a raw `EPERM` instead of waiting. Fix: shared `isLockContention` in `src/atomic-file.ts` (win32 only for EPERM/EACCES), plus `tests/lock-contention.test.ts`. A persistent real EPERM on Windows now reports "lock busy" after the existing timeout (5s, 30s for the Git cache) instead of failing at once.

## Product limitation found, not changed (needs a design decision)
The Package approval and confirmation panels (`PackagePanel` and `PreviewConfirm` without a cursor) are not paged. Ink squeezes the panel into the terminal height, so text overlaps when the content is taller than the terminal. A long working-directory path (deep Windows profile paths) adds wrapped rows. This reproduces on Linux with a long `TMPDIR` and a 24-row terminal. I worked around it in the test (`tui-package-journey` sets `rows` to 60). The fix would be to page these panels with the existing `previewViewport` ("Review n of m"), as the Updates tab does. This is a follow-up issue, not part of #46.
