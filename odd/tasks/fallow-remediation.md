- Real issue fix (final design, option B; supersedes the first cut of 43da2d2, which broke SPEC 10 by rejecting every non-canonical path): tracked-path trust depends on where the record comes from. Canonical `.agents/skills/<name>` / `.claude/skills/<name>`: unchanged. User-global (state file written only by Agent Depot; `installationTrust: "user-global-state"`): any in-home path as before 43da2d2 (containment only). Project manifest, non-canonical path: accepted only if it is a safe relative path, every component is a real directory (lstat walk, no symlinks), no component is `.git`, the basename equals the Skill name, `SKILL.md` (regular file) has frontmatter `name` equal to the Skill name, it is not the project root, it is not an ancestor of another tracked installation (`otherInstallationPaths`), and the user confirmed that exact path (`confirmedNonCanonicalPath`) before any mutation. Inspections expose `nonCanonicalPath`; `update apply` previews it with a WARNING and `--yes` confirms it (no new flag); `updateProjectSkillTransaction`, `removeProjectSkill` and `applySkillUpdate` refuse without matching confirmation. Implemented in `classifyTrackedInstallation` (project-installation.ts), wired through skill-update.ts and cli.ts.
- Behavior changes vs main: project non-canonical installs now need the validations above plus `--yes` on the exact path (before: any in-project directory, unvalidated, `--yes` only for modified content); a manifest pointing at e.g. `src/demo` or `.git/hooks/x` is rejected even with `--yes`. User-global unchanged. cli.test.ts:684 assertion restored to `/overlap/`.
- Residual risk: a hostile repository can still ship a directory with a faked `SKILL.md` (correct name) at a non-canonical path and a matching manifest entry; update/removal would then replace or delete it after the user confirms. Mitigated by the visible exact-path preview plus mandatory `--yes`; not eliminated because the project scope has no trusted record separate from the manifest. Reduced further by F2 below (`--yes` habit no longer suffices; the exact path must be typed).
- TDD: tests/path-containment.test.ts (5 tests) and tests/noncanonical-installation.test.ts (7 tests: confirmed update/remove, fail-closed without confirmation, hostile `src/demo`, `.git`/root/ancestor/symlink/basename/name mismatches, canonical unchanged, user-global trusted, CLI preview + `--yes`). RED observed for the second file (5 of 7 failed before implementation; the rejection matrix and canonical test were regression guards). First file RED observed: "hostile manifest installation path" (removal of `src/demo` accepted). Already GREEN and kept as regression tests: hostile skill names/tree paths on install (`..`, absolute, `a/../../x`, backslash, `./`, trailing slash, foreign prefix; project unchanged), symlinked tracked skill dir and symlinked skills root (update/remove refuse, outside untouched), unmanaged user-global removal with hostile explicit paths and symlinked skill dir.
- Suppressions: none added. Fallow only offers file-level (`// fallow-ignore-file security-sink`) or per-line comments; 91 sites (>20) would be noisy and a file-level ignore would hide future real sinks in the files that matter most. Classification lives here instead. Use `fallow security --gate new` (diff-based) in CI if a regression gate is wanted.
